# 官网填写扩展

官网填写目前为 Beta。目录收录、公开源码检查和本地表单回归均不等于登录后实测，具体范围见 [适配记录](website-adaptation.md)。工作台「运行状态」可检测扩展连接并下载安装包；也可使用仓库 Releases 中的 ZIP 与校验文件。

扩展可独立填写当前官网页面，也可以接收工作台的批量岗位。单页填写不需要启动工作台、配置邮箱或建立投递清单。每一项最终提交由用户在官网完成。

## 安装

在项目目录执行 `npm run build:extension`。输出：

- `dist/website-extension/`：可加载的扩展目录。
- `public/generated/website-extension.zip`：网页内提供的下载包，解压后有同名目录。

在 Chrome 打开 `chrome://extensions`，或 Edge 打开 `edge://extensions`，开启开发者模式，选择「加载已解压的扩展程序」，加载上述目录。将扩展固定到工具栏，刷新本机工作台。扩展更新后在管理页点击重新加载，并刷新工作台。

本机工作台连接限于 localhost / 127.0.0.1 的 3000、3107 端口及工作台各页面（包括简历诊断、投递清单和运行状态）。无需输入扩展 ID、执行器连接码或邮箱授权码。其他端口及远程工作台尚未接入。

## 直接填写当前页面

打开具体官网申请表，点击扩展图标，在面板里填写姓名、个人邮箱、手机号等资料，再点「填写当前页面」。首次使用某个站点时允许访问该站点即可。各项资料和简历附件均可留空；至少提供一项资料或一份附件才能开始。没有附件也会先填写其他资料，官网要求上传时单独提示。

点击填写会将资料保存在当前浏览器扩展中，下次复用；也可只点「保存资料」。附件支持 5 MB 以内的 PDF / DOCX / TXT，可移除后保存。首次打开时可沿用之前已交接到扩展的基础资料与附件；独立资料后续单独保存，不改动原批量任务。多段经历仍可通过工作台的批量功能交接。

填写结果会列出成功项数量和缺项。可补充资料后再次填写，已有内容不覆盖；登录、验证码、自定义选项和最终提交在官网处理。关闭面板后已启动的填写仍由扩展后台执行，重新打开可查看结果；后台重启中断时明确提示核对后重试。

## 批量操作（可选）

1. 在工作台的投递清单中，勾选带公司、职位和 HTTPS 招聘链接的官网岗位。填写了招聘邮箱的条目走邮箱投递。
2. 点击「官网批量填写」。选择简历附件；如果有多个申请入口，必须选定一个具体入口。
3. 核对个人资料后点击「发送到扩展」。这一步只保存任务，还没有开始填写。
4. 点击 Chrome / Edge 工具栏中的 Resume Grill 扩展图标，再点击「开始填写」，允许本批招聘网站的访问权限。
5. 扩展列出「需要处理」的岗位时，可在扩展补充普通缺项；登录、验证码和特殊控件请点击「打开官网核对」处理，再点「继续填写」。最终提交由你在官网完成。

### 哪些是必填

- **发送任务前必选**：一个 5 MB 以内的 PDF / DOCX / TXT 简历附件，以及 1–20 个有效官网岗位。多个申请入口必须选定一个。附件可以直接在填写窗口内选择或更换。
- **个人资料选填**：姓名、邮箱、手机号及其他资料都可留空，但建议提前填好前三项；填入的邮箱、电话和个人链接需符合格式。扩展读取具体官网表单后，才知道该站实际要求哪些字段，并列出待补充内容。
- **经历选填**：只有勾选「已核对」的经历才交给扩展；未核对也可先发送基本资料和附件。

按钮不可用时，窗口底部会显示具体原因。扩展中还有未结束的任务时，请先继续处理或清空旧任务。

### 扩展里没有任务

单个官网直接使用「填写当前页面」。需要批量处理时，点击面板顶部的「打开工作台」，或展开「批量任务（可选）」点击「刷新任务」。扩展优先使用当前标签页中的工作台，其次选择最近访问的本机工作台；没有找到时打开 `http://127.0.0.1:3000/applications`，需要先启动网页。若已发送任务但面板仍为空，先检查顶部的连接结果，再刷新任务。

更新扩展代码后，先运行 `npm run build:extension`，再到浏览器扩展管理页点击「重新加载」。下载 ZIP 安装的用户需要用新包替换原扩展目录里的文件，再重新加载。当前扩展版本为 `0.2.1`。

表单权限仅针对本批实际站点申请。遇到其他域名的登录或招聘系统，扩展先停住，在工具栏点击继续并允许当前站点后再传入资料。已允许某站点也不代表任意跳转都可接收当前申请资料。

多个入口不会默认选择第一条；只有招聘页已给出的申请入口或该岗位自己的来源页可以入队。没有识别到表单时先在原页进入具体申请表，再继续。

## 连接失败时

工作台和扩展必须位于同一个 Chrome / Edge 配置文件中；在其他浏览器或应用内打开工作台，无法连接已装在 Chrome / Edge 中的扩展。扩展管理页应显示版本 `0.2.1`，处于启用状态。打开面板后，顶部会显示找到的工作台地址；已经授权的地址会自动补装通信脚本并检查连接。

未授权时，点击顶部的「连接工作台」。面板会依次显示权限检查、通信脚本加载和往返检测，收到后台回应才显示「已连接」；权限拒绝、页面跳转、注入失败和消息超时会保留具体原因。工作台收到脚本就绪通知后会自行重新检测，不需要再手动刷新页面。若授权弹窗让扩展面板关闭，重新打开面板即可自动继续检测。

“运行状态”和填写窗口会显示实际连接错误。服务休眠后的首次回应最多等待 10 秒；重新检测只检查连接，不重复发送岗位。

## 状态和恢复

| 状态 | 含义 |
| --- | --- |
| 等待填写 | 已保存，尚未开页 |
| 正在打开 / 正在填写 | 当前执行步骤；暂停后等本步骤结束 |
| 需要处理 | 登录、验证、缺项、权限、加载超时或表单未识别；其他岗位继续 |
| 已准备 · 待核对提交 | 已尝试常见字段；仍需核对官网页面和上传结果 |
| 已手动确认提交 | 用户在官网提交后自行确认，不代表扩展读取到了服务端结果 |
| 已跳过 | 本批不再自动处理 |

资料、答案、当前批次、附件和标签页编号存储在扩展本机存储中，写入成功后才推进下一步。整批继续跳过已经准备的岗位；单项继续优先复用原标签页。标签页已关闭时，用户继续才会重新打开。浏览器或扩展重启后中断项停在待处理状态，需用户继续。

补充通用资料后，其他只缺通用资料的岗位会重新尝试。个性化答案按官网来源、公司、岗位和问题文字保存；验证码、密码、证件等在官网处理。新批次不能静默覆盖未处理的旧批次，先完成、跳过或清空旧任务。

## 表单覆盖

### 多段经历复用

选择附件后，工作台读取该附件文本，在本地识别教育、工作/实习、项目章节中带时间范围的条目。识别不调用模型；未知格式不会补造字段。展开「教育、工作与项目经历」可对照原文、逐段编辑、添加或删除，并复制单段文本。点击「保存经历」即可保存，无需连接扩展；准备整批时也会保存。核对勾选后才把经历交给扩展，修改任一条会取消核对状态。

经历按附件提取文本版本保存；相同文本复用已核对结果，正文变化后重新提取。扩展在持久化批次中保存经历，因此暂停和重启后仍保留。本地保存失败会提示，不会继续交接。

目前自动填写限于明确标有「教育经历 1」「工作经历 2」「项目经历 1」等编号的 fieldset/legend 或带 aria-label 的 role=group，以及 B站公开代码中的栏目标题与编号分组。类别内按简历顺序对应，只填写空白分组；缺少编号、重复编号、已有内容或无法识别的控件交给用户核对。官网没有足够分组时提示新增或复制，不自动点击未知网站的“新增经历”。B站规则通过渲染代码重建契约测试，不代表已完成登录后实测。

- 常见中英文标签、`autocomplete`、原生 input / textarea / select，以及开放的 Shadow DOM；增加常见 UI 组件的外置标签和必填标记。
- 使用原生值设置器及 input / change / blur / focusout 事件更新；检查页面保留值、原生校验和框架错误状态。
- 自定义单选仅在 combobox 与唯一可见 listbox 明确关联时精确选择，核对已选文本。无关联弹层、多选、多级地址、远程搜索仍可能需要手动处理。
- 只向明确标注简历的文件控件上传 PDF、DOCX、TXT；尊重其 accept 限制，已有附件不替换。
- 不默认勾选协议、不填写登录密码或验证码；无法识别的经历、日期组件、自定义选项及其他附件交回官网。
- 跨域 iframe 不注入，多页步骤由用户在官网切换，随后从扩展继续。

Lever 已加入基于公开申请页的基础字段适配、必答题组检查和附件标识核对；用裁剪后的真实 HTML 做本地回归。2026-10-24 检查了 10 家国内官网公开入口及部分脚本，补充共用组件和 B站规则。国内站点不把文件进入控件视为上传完成；B站依据公开代码中的上传结果展示核对，其他站点需用户检查上传结果。所有国内站点均未完成登录后真实浏览器测试，运行摘要会注明“实站待验证”。未实现自动点击最终提交。具体样本和限制见 [官网适配记录](website-adaptation.md)。

## 开发验证

源代码在 `src/browser-extension/`，共享契约在 `src/domain/website-automation.ts`，工作台入口与资料准备在投递模块。构建脚本使用 esbuild 输出 MV3 独立扩展，产物不提交 Git。

自动测试使用模拟 Chrome API、真实 DOM 测试环境和本地表单夹具，覆盖批量顺序、暂停继续、存储失败、重启恢复、关闭标签页、重复交接、域名权限、缺项复用和文件上传事件。测试不会访问真实招聘网站或提交申请。

后台监听器在模块执行时同步注册，存储初始化在处理消息内部等待，遵循 [Chrome 的 MV3 事件注册要求](https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers#register-listeners)。

主动连接使用 [Chrome scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting) 在本机工作台加载通信脚本；本机访问权限在点击时单独请求，未放开远程工作台。
