# BOSS 岗位与批量投递

实验功能，入口在工作台左侧「投递 → BOSS 投递」（`/boss`），与简历库、投递清单共用导航；窄窗口通过顶栏导航按钮打开侧栏。支持岗位准备及整批确认后执行。**批量联系、发送文字和图片仅通过隔离页面测试，尚未对真实招聘方执行验证**；真实页面已验证岗位读取和已有会话填写，不代表发送及图片入口已适配。

## 使用

```bash
npm run boss:preview
```

先运行工作台 `npm run dev`，再运行上述浏览器服务。打开终端输出的工作台链接（默认 `http://localhost:3000/boss#…`）；其他网页端口可替换链接的主机和端口，保留 `#` 后的本次凭据。凭据只存本标签页 sessionStorage，服务重启后使用新链接，不是邮箱授权码。启动服务不会自动连接浏览器。

工作台直接选择简历库中的已有简历，读取当前页岗位后勾选，再准备招呼语。可上传 PNG / JPG 并逐条编辑，点击「保存草稿」保存到本机 IndexedDB；重新打开可恢复，简历版本变化时不恢复旧稿。草稿不写入已投递记录。

`http://127.0.0.1:4327` 保留为独立诊断页，以下为诊断页操作：

1. 在普通 Chrome 保留已登录的 BOSS 搜索结果页。Chrome 144+ 需手动在 `chrome://inspect/#remote-debugging` 开启调试。
2. 点「连接 Chrome」，自行确认 Chrome 的授权提示，再选择要采集的页面。
3. 填写岗位方向，点「官网搜索」打开该方向的结果页；相同查询不会重复打开。然后填写已有简历中的相关经历，选择 PNG / JPG 简历图片，点「拉取并准备」。也可先「只读取岗位」，取消不想联系的岗位后再准备。
4. 逐条检查或修改招呼语、查看引用依据及对应图片。招呼语使用模板并引用原简历内容，当前没有调用模型。图片最多 3 张，单张 5 MB、合计 10 MB。

现有浏览器模式通过 CDP 连接所选页面和本批创建的后台页，不使用 Playwright 初始化整个日常浏览器，不启用 Debugger、不注入启动脚本。「官网搜索」在点击时导航原列表页；详情读取和投递使用后台页，原列表保留，不拦截官网请求、不转发任意键鼠。连接与导航计数可在诊断区查看。

工作台「官网画面」点「开始预览」后约每秒更新一帧；执行时显示本批当前后台页，平时显示所选列表。iframe 展示只读截图，并非直接嵌入 BOSS 网站。暂停、切走工作台标签页或离开模块会停止截图，**不会取消已经确认的投递**；停止投递请点「完成当前步骤后暂停」。断开或采集失败显示原因，需要手动重试。结束时点「断开」或 Ctrl+C，不关闭用户原浏览器。

## 批量投递

1. 在工作台选择简历、搜索并读取岗位，勾选要联系的岗位。可先读取完整 JD，修改每条招呼语，并选择 PNG / JPG 简历图片。
2. 点「核对本批投递」，查看全部公司、岗位、正文和图片。每批最多 10 个岗位；有联系记录或结果待核对的岗位自动排除。
3. 核对后勾选整批授权，再点「确认并开始批量投递」。BOSS 的沟通入口可能先发送账号设置的系统招呼，随后程序发送已核对的正文和图片；确认区会明确提醒。

每个岗位执行前重新核对链接、标题、公司和完整 JD；通过后只点击一次沟通入口。只操作本批创建的页面，聊天新页必须能追溯到该岗位页；不能确定收件会话就停止。每步先把发送意图落盘，再执行并读取页面回执。验证、频率限制、付费提示、用户接管、页面变化或缺失回执均会暂停，不自动重复点击或发送。

图片必须同时取得成功的上传响应，以及会话中新出现且匹配响应地址的图片；本地 blob 预览不能充当上传回执。CDP 对响应体使用有上限的持久缓冲，防止核验时响应体已从缓存移除；读取失败仍标记待核对，不回退为“预览可见即成功”。这不等于已确认招聘方收到或阅读。

「完成当前步骤后暂停」会保留当前步骤的核验结果，尚未执行的岗位可在下一批重新准备；已经联系或结果不明的岗位需要手动核对，不支持自动恢复剩余消息。刷新工作台只读取原批次；服务重启也不自动恢复发送。全部步骤都有回执的岗位写入普通投递记录，部分完成和结果不明的岗位留在「BOSS 执行批次」，不冒充完整投递。

日志与已选图片保存在已忽略的 `.boss-agent/boss-batches/`，其中包含招呼语、岗位和图片，需自行妥善保管。只保存结果编号和必要回执，不把 Cookie、登录资料或调试凭据写入日志。上传的是本批确认的图片，不自动点击「发送附件简历」等可能有额外条件的入口。

`node scripts/check-boss-delivery.mjs` 使用独立无界面浏览器、合成招聘页和断网代理，验证两岗位全文与图片发送、页面回执、重复确认、跨批次去重、身份错配阻断及回执缺失暂停；不会连接日常账号。真实 BOSS 页面结构、会话跳转和图片上传响应仍需进一步验证，不能保证所有页面版本可用。

该检查需要 Windows / Edge；上传夹具通过只转发到本机的代理和临时 HTTPS 服务返回响应，以验证 CDP 响应体读取。临时证书不写入系统证书库，测试结束清理。另有仅产生本地 blob 预览、不返回上传确认的反例，必须停在待核对状态。

## 连接状态

点「连接 Chrome」后，如果显示等待授权，需要在 Chrome 弹窗中手动允许；工作台会保持等待，不重复发起请求。Chrome 授权成功后，如果没有 BOSS 标签页，会自动在同一浏览器会话后台打开招聘页并接入工作台；只有一个已有 BOSS 页面时直接复用，多个时由你选择。页面不抢到前台，不另开浏览器、不新建登录资料，断开连接也保留该页面。若页面被关闭，可点「打开 BOSS 官网」恢复，重复点击或重连不会重复开页。所选页面关闭后也可通过刷新列表重新选页。

如果仍未连接，页面会区分授权等待超时、授权前连接关闭、调试握手未被接受及遗留调试地址已失效。旧地址文件不会被自动删除，登录资料不会被读取或重建。

## 完整 JD 核对

读取并勾选列表岗位后，点击「读取所选岗位 JD」。识别到登录或验证时停止后续读取，不绕过验证、不自动重试。遇到缺少公司、链接/标题/公司不一致、正文缺失或截断时，详情不参与准备，界面明确显示原因。沟通入口只检查是否存在及是否禁用，不点击，识别到入口也不代表已具备真实发送能力。

详情内容仅绑定本次列表快照；列表变化或重新读取后失效。成功读取后清除旧招呼语，点击「准备招呼语」使用已核对的正文；仍未读取详情的岗位继续使用列表摘要并明确提示。当前匹配仍是关键词/别名与简历原文引用，没有调用模型。

新增详情读取已通过隔离浏览器中的 CDP 集成回归，覆盖同会话后台临时页、完整 JD 进入准备、临时页关闭及原列表不跳转；已在一个真实岗位核对通过（314 字正文，临时页关闭且原列表保留）；这不代表所有岗位或页面版本均适配。

自动打开回归：`node scripts/check-boss-auto-open.mjs`，使用隔离浏览器和模拟页面，覆盖会话沿用、复用去重及关闭后恢复。

## 真实页面只读验证

浏览器服务运行且已手动连接、选择 BOSS 列表页后，可运行：

```bash
node scripts/verify-boss-live.mjs
```

脚本只读取当前列表和其中一个有公司名称的岗位详情，不连接浏览器、不搜索、不点击沟通或发送。核对详情身份、正文长度、原列表是否保持及临时页关闭请求；遇到登录、验证或不匹配会返回未通过。完整结果写入已忽略的 `.boss-agent/e2e/live-detail.json`，不包含本机连接凭据、Cookie 或页面私有查询参数。该报告用于说明实际验证结果，不能用隔离测试代替真实账号验证。

## 在工作台填写已有会话

普通 `npm run boss:preview` 已支持本机草稿填写，无需测试开关。核对招呼语后点击「填入已有会话」→「打开已有沟通」，在 Chrome 手动选好现有会话，再回工作台「检查当前输入框」。确认公司、岗位及当前收件人后，点击「填写到 Chrome，不发送」。文字会保留在 Chrome，供你检查并自行决定是否发送。

程序只接受唯一、可编辑且空白的输入框，不覆盖已有草稿。会话名称识别是辅助信息，**岗位与收件人的对应仍由用户人工核对**；未识别名称时会明确提示。核对凭据绑定页面、招呼语和输入框快照，30 秒过期且只能用一次；草稿变化、页面变化或已识别的会话名称变化均须重查。填好后读回核对，不写为“已投递”，不点击发送或沟通、不上传图片。

## 已有会话填写测试（不发送）

开发验证可用 `node scripts/boss-preview.mjs --attach --allow-draft-test`；该开关仅开放带标记文本的测试接口；工作台的普通草稿填写通过独立的核对凭据执行。测试只允许在已有沟通页唯一且空白的输入框写入带「【填写测试，请勿发送】」标记的短文本；不覆盖用户草稿，不点击沟通或发送，不触发键盘快捷键。可选择读回后清除测试文字；若读回内容已变化，不清除用户的新内容。

已在用户手动打开的真实已有会话验证 `div#chat-input.chat-input[contenteditable]`：37 字输入后等待并读回一致，清除后再次确认输入框为空。没有发送或上传。结果保存在已忽略的 `.boss-agent/e2e/live-draft-test.json`，不包含聊天内容或联系人信息。该测试不代表新建沟通、真实发送或图片上传已验证。

2026-11-15 再次验证：已登录 Chrome 的真实已有会话中，26 字标记文本写入、读回及清空均通过，最终输入框为空；没有点击沟通、发送或上传。出现“没有输入框”时可通过已鉴权的 `/composer-diagnostics` 检查文档就绪状态、可见控件和内嵌页面结构；诊断不返回会话正文、联系人或 URL 查询参数。

## 模拟执行

核对招呼语后点击「运行模拟测试」。本机服务会临时启动独立无界面 Chrome / Edge，只打开内置模拟会话，拦截所有外网请求，不连接已登录的 BOSS。按岗位依次填写文字、输入真实图片文件，再读取页面回执，比较文字与图片 SHA-256。点击暂停会完成当前步骤的回执核验，再停止后续步骤。

发送意图先写入 `.boss-agent/simulations/` 日志，完成后再记回执。同一任务编号重试只返回原结果，核对内容变更会拒绝复用编号。服务中断、收件会话变化或缺失回执时标记待核对，不自动重发。工作台刷新后按本标签页的任务编号重新读取；本机服务日志用于恢复结果，**不自动恢复发送**。新建测试会使用新编号，这是一次新的模拟执行。

结果写入浏览器 IndexedDB，在「投递记录 → 浏览器模拟测试」单独查看，不计入真实投递或漏斗。普通准备接口只接收图片元信息；点击模拟测试时，图片内容会传给本机服务用于测试页面文件输入，不发给 BOSS，也不写入服务端执行日志。

验证命令：`node scripts/check-boss-simulation.mjs`，覆盖两个模拟岗位的文字与图片回执、重复请求、核对内容变更与日志恢复。队列还单独测试会话错配、回执不符、写入失败及暂停。

## 当前边界

- 读取当前页卡片，按方向和岗位别名筛选；不自动翻页。工作台点击「读取所选岗位 JD」后，顺序打开后台临时详情页，复用选中页面的浏览器会话，核对链接、标题和公司，读取完整正文后关闭临时页。只有核对通过且正文未截断时才用于后续准备；原列表页不跳转。岗位去重，输出链接去掉查询参数；私有字体薪资不猜测数字。
- 准备草稿、诊断和模拟均不联系招聘方。只有工作台整批核对后的执行接口可以发送；简历、岗位或内容变化后需重新核对，过期快照不能生成新草稿。
- 普通准备只接收图片元信息；点批次核对后图片传到本机服务校验，确认执行后才写入本地批次目录并用于官网图片输入。最多 3 张、单张 5 MB、合计 10 MB；模拟数据独立存储，不计入真实投递。
- 连接已有浏览器不复制登录资料、不读取其他页面内容。调试授权本身范围较大，结束后可在 Chrome 关闭。可用 `--attach=ws://127.0.0.1:端口/devtools/browser/...` 指定本机地址。
- 单独启动专用测试浏览器可用 `node scripts/boss-preview.mjs`。该模式仅用于实验，其拦截规则不用于现有日常浏览器；曾触发官网验证和空白页，未确认稳定。

## 验证

```bash
node scripts/check-boss-preview.mjs
node scripts/check-boss-live-preview.mjs
```

使用独立无界面浏览器和合成页面，不触碰日常浏览器。覆盖不自动连接、不主动刷新、不拦截官网和扩展请求、岗位解析与去重、筛选及招呼语/图片预览、过期快照校验、实时 iframe 像素变化、暂停与并发限频、手动截图、连续跳转停止采集及断开保留浏览器。

真实页面此前已完成手动登录、搜索及查看岗位描述。早期全页拦截挡住了官网脚本和读取接口，已从现有浏览器模式移除，改为按需连接页面的 CDP 实现。真实页面已读取 15 个岗位并筛选生成 11 条演示草稿，另核对过一个完整 JD 和已有会话的填入/清除。此次开发未向真实招聘方发送消息或图片；真实发送兼容性待验证。

连接实现位于 `src/browser-agent/boss-reader.ts`，筛选与草稿准备复用 `src/features/applications/website/lib/boss-preparation.ts`。真实测试使用显式标记的演示简历与测试图片，不代表这些岗位已根据用户真实简历完成适配。
