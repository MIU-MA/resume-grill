# 官网邮箱投递

入口：工作台首页或左侧导航的「邮箱投递」，路径 `/applications`。无需配置模型，也不需要先生成面试练习。

## 启动和使用

使用 Node.js 22.13 或更新版本。在项目目录安装依赖后，分别在两个终端运行：

```powershell
npm install
npm run dev
```

```powershell
npm run mail-agent
```

1. 打开 `http://localhost:3000/applications`，点击「连接邮箱」。
2. 复制执行器终端中的连接码，连接本机执行器。连接码每次启动重新生成。
3. 在 QQ／163 邮箱设置中开启 SMTP 服务，生成授权码。在工作台填写邮箱、发件人姓名和授权码，点击「验证并连接邮箱」。验证只检查连接和登录，不发送测试邮件。
4. 选择简历原文件（PDF、DOCX、TXT，最多 5 MB）。该附件随本批每封邮件发送，不用逐条重选。
5. 在「粘贴招聘链接」中每行放一个官网岗位详情页的 HTTPS 地址，点击「整理到清单」。依次读取各页面，自动带入公司、岗位和明确的招聘邮箱。重复链接跳过，读取失败的链接保留在输入框里供重试。
6. 已连接邮箱后，主题和基础正文自动填好，使用发件人姓名和页面岗位信息，不生成未经提供的经历。手动改过的邮件不会被自动覆盖。资料完整时岗位字段默认收起，需要时展开修改；未识别的信息或多个候选邮箱需补充核对。官网特殊邮件标题要求会提示出来，请按要求修改。
7. 点击「预览可投递」，只预览已补全的草稿，待补充项继续保留。统一核对官网招聘用途、邮件和附件，勾选一次确认后发送。每批最多 20 封，逐封发送，邮件间隔 5 秒。每封只有一个收件人。

自动识别优先使用网页中的 JobPosting 结构化数据，其次使用明确的岗位标题、字段标签、网站名称。多个岗位的列表不会自动选择第一个岗位；客服、隐私等邮箱不会被默认选中。没有可读取的页面时仍可用「补录」手动填写。首次连接邮箱后，常规流程是「选附件 → 批量粘贴链接 → 核对预览 → 发送」。

QQ 使用 `smtp.qq.com:465`，163 使用 `smtp.163.com:465`，均校验证书并使用 TLS。密码框填写授权码。QQ 的入口说明见 [QQ 邮箱官方帮助](https://help.mail.qq.com/detail/106/985)，163 见 [网易邮箱帮助中心](https://help.mail.163.com/)。

## 记录与中断

- 关闭网页后，本机执行器继续处理已确认的批次。关闭执行器或电脑后不能继续发送。
- 「暂停」停止后续邮件；已经在发送中的一封会等待结果，无法撤回。
- 邮箱服务接受邮件后显示「已提交邮箱」。这不等于招聘方已收到或已读，也不能判断是否进入垃圾箱；退信需要在邮箱中查看。
- 发送出错后整批暂停。明确失败的邮件可手动重新加入队列，再点击「继续发送」。不自动重试。
- 连接在提交阶段中断、执行器在发送中退出时，标为「待核对」。先检查邮箱服务的发信查询或日志，再标记已发送或取消；SMTP 客户端发信未必同步到网页版“已发送”，不能只据此判断失败。
- 相同发件邮箱、收件邮箱、岗位名称的记录会阻止重复投递；更改主题或附件不会绕开检查。不同公司共用招聘邮箱时，在岗位字段带上公司名称或岗位编号。
- 重启后未发送的邮件保持暂停，需重新连接原发件邮箱和姓名，再点击继续。结果不确定的邮件不会重发。

浏览器的 IndexedDB 保存待投递草稿和附件，关闭标签页不会清除；清理浏览器存储会丢失草稿。连接码只保存在当前标签会话的 sessionStorage 中。邮箱授权码不写入浏览器存储或磁盘，只保存在本机执行器内存，退出后清除；如需撤销授权码，请在邮箱服务商的设置中操作。

本机执行器将邮件正文、收件人、来源、状态、附件等保存在项目的 `.mail-agent/` 目录，已加入 `.gitignore`。备份时复制整个目录。记录最多 2000 条；不要只删除发送记录，否则将失去对应的防重复保护。遇到记录损坏或磁盘写入失败时执行器停止，不会丢弃旧记录后继续发送。

## 网页部署后的连接方式

本功能由「网页工作台 + 用户本机执行器」组成，网站服务器不保存或代用用户的邮箱授权码。线上网页仍需要用户在自己的电脑启动执行器，并指定唯一允许的网站来源：

```powershell
$env:MAIL_WORKBENCH_ORIGIN='https://你的工作台域名'
npm run mail-agent
```

来源必须是 HTTPS，不带路径、末尾斜杠或通配符。本机开发默认允许 `localhost` 和 `127.0.0.1` 的 3000／3107 端口。执行器只监听 `127.0.0.1:4318`，所有接口校验来源、Host 和连接码。浏览器如提示访问本地网络，需要用户允许；浏览器或企业策略禁止此访问时，请先使用本地工作台。不同浏览器的线上到本机连接尚未逐一验证。

这不是一个公开的发信后端，请勿将执行器端口转发或部署到公网。项目其余模型接口的上线鉴权、密钥处理和限流仍需单独完善。

## 当前边界

只读取用户提供的单个招聘网页及有限跳转，不搜索或遍历整个网站，不猜邮箱地址，不绕过登录、验证码或访问限制。读取时限制公网 HTTPS 地址、DNS 解析结果、重定向、响应大小和超时。脚本加载、登录后显示、图片中的邮箱可能无法读取，可打开官网核对后手动填写。

网页中的邮箱及上下文作为待核对资料，不视为发送指令；`mailto:` 中的抄送、密送、主题、正文参数不会进入邮件。当前不支持官网在线申请表、BOSS 直聘、定时无人值守搜岗、收件箱回复同步或回执追踪。

测试使用本地模拟 SMTP 服务验证邮件和附件，不向真实招聘邮箱发送。真实 QQ／163 发信仍需使用自己的授权码完成首次验证。
