# 官网邮箱投递

入口：工作台首页或左侧导航的「邮箱投递」，路径 `/applications`。无需配置模型，也不需要先生成面试练习。

## 启动和使用

使用 Node.js 22.13 或更新版本。在项目目录安装依赖后，分别在两个终端运行：

```powershell
npm install
npm run dev
```

```powershell
npm run mail-agent
```

1. 打开 `http://localhost:3000/applications`，在「投递设置」保存默认姓名、邮箱、简历和模板。主题和正文支持 `{{公司}}`、`{{岗位}}`、`{{姓名}}`、`{{发件邮箱}}`，也支持英文 `company`、`role`、`name`、`email`；名单缺少岗位时可套用默认岗位。已手动修改的邮件不会覆盖，需要时在邮件详情点击「重新套用模板」。
2. 需要自动读取页面时，复制执行器终端中的连接码，连接本机执行器。连接码每次启动重新生成；读取页面不需要邮箱授权码。
3. 需要发送邮件时再连接邮箱。在 QQ／163 邮箱设置中开启 SMTP 服务，生成授权码。在工作台填写邮箱、发件人姓名和授权码，点击「验证并连接邮箱」。Windows 默认勾选「记住本机」，可取消。验证只检查连接和登录，不发送测试邮件；只有验证成功后才保存。
4. 点击附件名称直接选择简历文件（PDF、DOCX、TXT，最多 5 MB），可复用简历库中保存的原附件和 PDF 修改稿。没有已有附件时默认选用当前简历；若之前选的是当前修改稿对应原稿的同一版本，会跟随到直接修改稿，其他自选附件保留。文件名和保存时间用于核对版本；修改文字只暂存，点击「保存 PDF 并下载」后才生成新附件。粘贴文本可以先保存为 PDF 修改稿。该附件随本批每封邮件发送，不用逐条重选；已预览或发送的历史附件快照不会改变。
5. 切到「官网链接」直接展示招聘官网目录，点击公司即可打开原站并选择职位，无需先添加链接或连接执行器。「查找其他官网或岗位链接」可展开输入 HTTPS 地址查找；结果标明招聘入口、岗位详情、在线申请及来源。勾选岗位详情后点击「使用所选岗位」，自动带入公司、岗位和明确的招聘邮箱。已有链接时，展开「已有具体岗位链接」，每行粘贴一个详情链接，再点击「整理到清单」。重复链接跳过，读取失败的链接会列出，也会保留在输入框里供重试。
6. 「名单 / 招聘正文」支持每行粘贴公司、岗位、招聘邮箱，或导入 CSV／TSV。多个职位的正文每段从「公司：」开始，或用 `---` 分隔。无需模型或执行器即可整理名单、套用模板。缺项保留在表格中直接补充；有多个候选邮箱时在「查看」中选择。来源链接和岗位要求选填，特殊邮件标题要求仍需核对。
7. 勾选要发送的条目，点击「预览并发送」。只预览已勾选且补全的邮件，集中显示公司、岗位、收件人和主题，正文按需展开。核对招聘用途、邮件和附件，勾选一次确认后发送。未选中、待补充和官网申请的条目继续保留。每批最多 20 封，逐封发送，邮件间隔 5 秒。每封只有一个收件人。

CSV 示例（支持 UTF-8、带 BOM 的 UTF-16 和常见中文 Excel CSV；文件不超过 512 KB）：

```csv
公司,岗位,邮箱,来源链接,岗位要求
示例科技,前端工程师,jobs@example.com,https://example.com/jobs/frontend,熟悉 React 和 TypeScript
另一家公司,前端实习生,hr@example.org,,
```

表头支持中文或英文；无表头时按「公司、岗位、邮箱、来源链接、岗位要求」排列。正文含逗号或换行时使用 CSV 双引号。相同邮箱和岗位跳过重复项，同一招聘页中的不同岗位保留；超出本批剩余容量会提示分批导入，不会只保存部分条目。

自动识别优先使用网页中的 JobPosting 结构化数据，其次使用明确的岗位标题、字段标签、网站名称。多个岗位的列表不会自动选择第一个岗位；客服、隐私等邮箱不会被默认选中。没有可读取的页面时仍可用「补录」手动填写。保存默认设置后，名单投递流程是「粘贴名单 → 补缺项并勾选 → 核对预览 → 发送」。「官网链接」模式保留官网查找、读取和正文补充；自动读取和查找需要本机执行器，不需要模型或邮箱授权码。

查找只从实际页面链接和 JobPosting 元数据提取地址，不猜测招聘路径。每次最多请求 6 个页面，沿招聘入口深入 2 层，结果上限 100 个链接；使用约 18 秒的读取预算，DNS 解析可能稍延长结束时间。同一主机（含 www 别名）的招聘入口会继续读取，跨域招聘系统只列出原站入口，可核对后复制地址重新查找。部分页面失败时保留已发现的结果。有明确在线申请地址且没有招聘邮箱的岗位，显示官网申请入口，在原站填写后可手动登记已投；登记保存在浏览器，可撤销，与执行器的邮件发送记录分开。其他未识别到邮箱的岗位仍需核对和补充，不会自动视作已投递。

QQ 使用 `smtp.qq.com:465`，163 使用 `smtp.163.com:465`，均校验证书并使用 TLS。密码框填写授权码。QQ 的入口说明见 [QQ 邮箱官方帮助](https://help.mail.qq.com/detail/106/985)，163 见 [网易邮箱帮助中心](https://help.mail.163.com/)。

输入完整的 `@163.com` 地址后会自动选择「网易 163 邮箱」；默认投递设置保存的地址也会识别对应类型。在网易网页版邮箱的「设置 → POP3/SMTP/IMAP」开启 SMTP 服务，填写客户端授权码后点击「验证并连接邮箱」。此操作验证连接和登录，不发送邮件。当前网易仅支持普通 163 邮箱，126、yeah 和企业邮箱尚未接入。

## 记录与中断

- 关闭网页后，本机执行器继续处理已确认的批次。关闭执行器或电脑后不能继续发送。
- 「暂停」停止后续邮件；已经在发送中的一封会等待结果，无法撤回。
- 邮箱服务接受邮件后显示「已提交邮箱」。这不等于招聘方已收到或已读，也不能判断是否进入垃圾箱；退信需要在邮箱中查看。
- 发送出错后整批暂停。明确失败的邮件可手动重新加入队列，再点击「继续发送」。不自动重试。
- 连接在提交阶段中断、执行器在发送中退出时，标为「待核对」。先检查邮箱服务的发信查询或日志，再标记已发送或取消；SMTP 客户端发信未必同步到网页版“已发送”，不能只据此判断失败。
- 相同发件邮箱、收件邮箱、岗位名称的记录会阻止重复投递；更改主题或附件不会绕开检查。不同公司共用招聘邮箱时，在岗位字段带上公司名称或岗位编号。
- 重启后未发送的邮件保持暂停。记住本机时自动验证并恢复原邮箱，未记住时需重新填写授权码；仍须手动点击继续。结果不确定的邮件不会重发。恢复失败可重试「恢复已保存邮箱」或更新授权码。

浏览器的 IndexedDB 保存待投递草稿、附件、勾选条目、默认姓名和邮箱、模板及手动登记的官网申请记录，关闭标签页不会清除；清理浏览器存储会丢失这些数据。连接码只保存在当前标签会话的 sessionStorage 中，每次执行器重启仍需使用新连接码。

「记住本机」目前支持 Windows，使用 [DPAPI 的 CurrentUser 保护](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata)，把邮箱配置加密保存在 `.mail-agent/credentials.dpapi`，不把授权码写入浏览器、发送记录或日志。文件依赖当前 Windows 账户，复制到其他电脑或账户不能直接恢复。未勾选时只在此次执行器运行内使用；取消勾选并重新验证会移除旧的保存授权。

「断开邮箱」暂时断开，保留已保存授权；「忘记授权并断开」删除本机密文并清除当前连接。若要撤销授权码本身，请在邮箱服务商设置中操作。其他操作系统目前不提供保存选项，也不会退回明文保存。

本机执行器将邮件正文、收件人、来源、状态、附件等保存在项目的 `.mail-agent/` 目录，已加入 `.gitignore`。备份时复制整个目录。记录最多 2000 条；不要只删除发送记录，否则将失去对应的防重复保护。遇到记录损坏或磁盘写入失败时执行器停止，不会丢弃旧记录后继续发送。

## 网页部署后的连接方式

本功能由「网页工作台 + 用户本机执行器」组成，网站服务器不保存或代用用户的邮箱授权码。线上网页仍需要用户在自己的电脑启动执行器，并指定唯一允许的网站来源：

```powershell
$env:MAIL_WORKBENCH_ORIGIN='https://你的工作台域名'
npm run mail-agent
```

来源必须是 HTTPS，不带路径、末尾斜杠或通配符。本机开发默认允许 `localhost` 和 `127.0.0.1` 的 3000／3107 端口。执行器只监听 `127.0.0.1:4318`，所有接口校验来源、Host 和连接码。浏览器如提示访问本地网络，需要用户允许；浏览器或企业策略禁止此访问时，请先使用本地工作台。不同浏览器的线上到本机连接尚未逐一验证。

这不是一个公开的发信后端，请勿将执行器端口转发或部署到公网。项目其余模型接口的上线鉴权、密钥处理和限流仍需单独完善。

## 当前边界

支持单页读取及有限范围的招聘链接查找，不进行全网搜索或完整网站遍历，不猜邮箱地址，不绕过登录、验证码或访问限制。读取时限制公网 HTTPS 地址、DNS 解析结果、重定向、响应大小和超时；查找时额外限制主机范围，跨域跳转不继续读取。脚本加载、登录后显示、图片中的邮箱可能无法读取，可打开官网核对后手动填写。

网页中的邮箱及上下文作为待核对资料，不视为发送指令；`mailto:` 中的抄送、密送、主题、正文参数不会进入邮件。当前不支持自动提交官网在线申请表、BOSS 直聘、定时无人值守搜岗、收件箱回复同步或回执追踪。

测试使用本地模拟 SMTP 服务验证邮件和附件，不向真实招聘邮箱发送。真实 QQ／163 发信仍需使用自己的授权码完成首次验证。
