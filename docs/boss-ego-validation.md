# ego 与 BOSS 验证记录

2026-11-17，ego(lite) 0.6.3.14，ego-browser v2.2.1。入口：`npm run boss:ego`。

## 已修复并接入

- 工作台服务通过 ego 自有 Node/CDP 接口创建独立任务空间，复用原有岗位采集、JD 核对、批次准备、发送队列及回执代码；不再只是用 CLI 手动运行几个项目函数。
- 图片选择器只匹配纯图片控件，排除同时接受 PDF、Word、PPT 的附件入口；多个纯图片控件时仍拒绝猜测。
- 真实会话支持 `.friend-content.selected`；身份绑定具体 DOM 列表项及其身份信息，同名会话、替换或切换列表项会失效，聊天摘要变化不影响身份。不会仅凭姓名放行。
- 支持真实本人消息样式 `.message-item.item-myself`，正文核验排除气泡外的时间和已读状态。
- PDF 排版换行合并为完整语句后选择引用，不按半行或固定字符数截断。无法取得适合长度的语句时提示人工核对。
- 修复搜索跳转时清空岗位快照引起的异常；读取完成后再保存快照。搜索保留 URL 中已选城市，未指定时默认全国。
- ego 沟通新页追踪真实 opener，仅接入自有岗位页产生的弹窗。用户接管后停止命令，断开时保留用户控制的空间。

## 真实试投后的修正

一次经授权的非大厂真实试投中，官网默认招呼与程序自定义招呼各发送了一条；其中自定义招呼实际已送达，但回执把嵌套在 `.text` 内的「送达」状态也当作正文，误判失败。批次暂停后，用户指出重复联系；已停止并关闭真实服务，没有继续发送图片或联系下一家。具体目标及消息回执保存在本机忽略目录，不提交到仓库。

已修复：正文优先读取 `.text-content`；批次只核对官网自动招呼，不追加自定义文字；没有新消息 ID 与送达状态则暂停；记录实际官网消息及其来源，保留原草稿供对照；官网已经显示「继续沟通」时拒绝重复联系。新界面拒绝启动仍会追加文字的旧执行器。

此后只进行隔离回归，不再向真实招聘方发送。修正后的 980 项测试、架构、类型检查和生产构建通过；隔离双岗位测试确认每家公司只有一条官网自动招呼，自定义文字发送次数为零。真实图片上传和修正后的整批实发流程仍不能宣称已通过。

## 其他运行时的隔离测试

随后测试了 [agent-browser](https://github.com/vercel-labs/agent-browser) 0.43.0，使用独立会话、空配置和本机 Chrome，限制访问回环地址。不迁移用户登录资料、不打开 BOSS、不使用真实简历，不加入项目依赖。

- 通过中文输入、下拉选择、contenteditable、选择合成测试附件、滚动到底部填写和刷新后读取 localStorage。
- 使用该会话提供的 CDP 地址，项目现有 `BossBrowserReader` 连接成功，能发现本机测试页面；断开项目读取器后页面仍保留，最后显式关闭独立会话。
- 这验证的是另一种 Chromium 会话管理方式，没有验证招聘网站适配、已有登录态或真实投递，也不代表换了更轻量的浏览器内核。

本机存在 Docker 命令，但 Docker Linux 引擎未运行；本轮没有启动 Docker Desktop、安装 WSL 或下载 Steel/Lightpanda 容器。原始结果位于已忽略的 `.boss-agent/e2e/agent-browser-result.json`。
