# 脱敏验收清单

每次修改解析、追问、覆盖率或批注逻辑后，使用脱敏材料完成以下场景。不要记录 API Key 或真实个人信息。

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 技术术语 | 对专业术语只提交“不懂批注” | 模型先解释并改写问题；覆盖率和有效轮次不增加 |
| 指标口径 | 回答成果数据但不说明基线 | 系统继续追问基线、统计范围或归因 |
| 职责边界 | 回答团队成果但不说明个人贡献 | 系统追问个人决策、行动和协作边界 |
| 状态恢复 | 完成一轮后刷新并打开本地简历 | 已完成会话、批注和已掌握状态仍存在 |
| 失败降级 | 让总结请求失败 | 问答仍保存，报告显示总结失败而不是丢失会话 |
| 盲区闭环 | 在报告中标记已掌握并重新测试 | 状态持久化，重新测试创建新版本且不覆盖历史 |

发布前还应确认：

- PDF 原文件不会上传到应用服务器。
- 没有模型时规则预览可以完成简历分析。
- 真实模型返回 Markdown 代码块或前后解释时仍能解析 JSON。
- 3 轮前不能结束，5 轮时必须结束。
- 同一声明多次测试只计为一条已完成声明。
